# Comparison Results — AI corrector (PINN) vs baseline predictor-corrector

Generated by `run_comparison_batch.py`. This folder holds the constraint-check study
(does the AI/PINN constraint corrector reduce heat-flux / g-load violations while still
reaching the target?).

## Files
- `comparison_metrics.csv` — one row per simulation run. Columns:
  `run, guidance_type, wind, max_heat_flux_kW, max_g_load, final_mach, final_altitude_m,
   final_angular_distance_deg, heat_flux_violation, g_load_violation, reached_target,
   classification, propagation_time_s`
  - `propagation_time_s`: wall-clock of the full propagation (incl. guidance + AI corrector)
    -> use to quantify the AI's computational overhead
  - `guidance_type`: `PINN_baseline` (no AI) or `PINN` (AI corrector)
  - `wind`: 1 = wind model on, 0 = off
  - runs are paired: `cmp_nw_0001` / `cmp_w_0001` (no-wind / wind), same seed across modes
- `comparison_summary.txt` — human-readable AI-vs-baseline table (per wind setting + paired fix count)
- `comparison_plots.png` — outcome-rate bars + peak heat-flux / g-load histograms
- `failures.log` — runs that raised an exception (batch continues regardless)

## Per-run trajectories
Full `.dat` outputs are written by `produce_simulation` to:
`SimulationOutput/{Wind|NoWind}/PINN{,_baseline}/{Success|Acceptable|Fail}/run_*`

## Re-run analysis only (no simulations)
```
python run_comparison_batch.py --analyze
```
